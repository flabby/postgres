# PG18 / Taurus 实例内存保护器首版设计

状态：v0.2，设计及分阶段实现。已实现观测、进程选择、安全取消/终止和并行 leader 关联；真实 Linux 压力及 Taurus 认证尚未完成。实际实现差异与验证记录以 ../plans/2026-09-28-instance-memory-protector.md 的 2026-09-29 记录为准。本文剩余章节保留完整首版目标，不表示全部已交付。

## 1. 交付目标和边界

只做实例压力采集、普通用户 backend 选择、安全取消/终止、效果复查和事件记录。目标是在约定负载矩阵中，以部分请求失败或连接断开换取实例持续服务。不能承诺任意突发下零 OOM，也不能承诺请求只变慢。

不做 SAL/IPC/维护任务分桶预算、任务授信、DDL 队列、SQL 精细内存记账、jemalloc 主动 purge、自动重试、连接池。现有 max_connections 和平台连接池策略继续有效；本功能不自行加入连接准入系统。

基线为 PostgreSQL REL_18_STABLE。Taurus 的 PG、SAL 同属一个实例 cgroup；jemalloc 5.2.1，现有 MALLOC_CONF 为 background_thread:true,narenas:4,dirty_decay_ms:5000。首版不调整 allocator 配置。

## 2. 最小架构

一个具有固定共享内存、无需数据库连接的专用 background worker 执行保护循环。后端仅增加有界身份/请求状态和安全中断处理，不在 palloc 热路径记账。

模块职责：

- PressureSource：发现 cgroup，采集上限、占用、时间及诊断分项。
- VictimSelector：仅从可信 PG 注册信息识别用户 backend，结合 OS 私有内存近似值排序。
- ActionDispatcher：发布带代次的取消/终止请求，唤醒目标；不直接做 allocator 操作。
- ProtectionController：状态转换、在途动作限制、恢复与无进展停止。
- EventStore：固定容量事件环及只读诊断接口。

管理循环不用 SQL 查询 pg_stat_activity，不依赖新建数据库连接成功；不在压力下打印完整 MemoryContext 树。固定共享结构随 max_connections 有界分配，计入实际 cgroup 占用。

## 3. 压力口径

L 为可信实例有效上限，U 为实例 cgroup memory.current，H=max(0,L-U)。L 来自平台实例限额与本 cgroup 有限 memory.max 的约束；未知、无限或无法确认实例边界时不得进入 enforce。

同时发现可见祖先约束。若祖先与其他实例共享，不把祖先剩余额度当成本实例独占容量；祖先压力单独记录并告警，本实例单独动作不能承诺解决邻居导致的父级 OOM。存在更紧的外部约束且平台无法提供有效边界时，enforce 配置验证失败。

U 已包含 SAL、IPC、PG 和同域页缓存等，不再减去 SAL/IPC 预留，不累计进程 RSS。memory.stat 中 anon/file/shmem 和 memory.events 用于解释原因；file 含可回收与不可立即回收部分，不直接从 U 扣掉全部 file。swap 使用与 swap 上限单独展示，H 不命名为系统可用内存。

cgroup 路径变化、限额变化每次采样检查必要元数据并切换配置代次。采样失败或超龄时，不基于历史压力选择新目标；已有退出/清理继续。

## 4. 参数和内部策略

用户侧仅两个拟议参数（名称尚属设计接口）：

| 参数 | 权限和行为 |
| --- | --- |
| memory_protection_mode | 平台/超级用户；off、observe、enforce；observe 不发送取消或终止 |
| memory_protection_headroom | 平台/超级用户；字节数 A；enforce 要求 0<A<L，重载校验 |

不存在用户强制填写的 SAL、IPC、work_mem 等预算。采样与动作策略来自版本化平台规格模板，状态视图必须展示实际值，不能隐藏生效配置。

以下为原型起点，不是生产默认值：采样 100 ms；连续两个样本 H<=A 进入 PRESSURE；H<=A/2 立即进入 CRITICAL；H>=1.5A 连续三个样本退出本轮；配置校验要求 1.5A<L。取消宽限上限 200 ms，并每个样本重评；CRITICAL 不等待宽限结束。进程退出等待初始上限 1 s；全实例同时在途目标最多两个，一般状态最多一个。统计样本超过 300 ms 视为过期。

平台必须按检测、目标响应、退出清理的尾延迟校准 A：A 应覆盖该窗口内内存增长和清理空间。没有生产压测数据时只能 observe，不能把上述原型数值作为已认证模板。恢复阈值无法达到时记录持续压力，不能无限清理。

## 5. 状态与动作

NORMAL → PRESSURE → CRITICAL；每个状态都可进入 STALE，恢复后重新判断。

- NORMAL：只采集和更新候选摘要。
- PRESSURE：先找占用明显较大的普通空闲连接并终止；没有合适空闲连接时取消选中的活跃查询。具体最小收益阈值为平台模板项，原型取 max(64 MiB,A/16)，用于避免清理大量小连接。
- CRITICAL：可以直接终止允许处理的用户连接；目标排序仍遵守保护名单，不扩大到后台进程。
- STALE：停止发起新动作，保留已发送动作的完成跟踪。

取消宽限到期后，只有实例仍处于压力状态，才考虑升级。若原语句已结束，不将旧语句的取消/升级请求套到下一条语句；要么记录完成，要么针对当前会话重新选择并发布新的会话终止动作。取消无效果不等于可跳过安全退出。

每个动作后检查目标状态和新 cgroup 样本。发送成功、取消完成、进程退出、实例压力缓解四个事件分别记录。全局占用下降受其他进程影响，不能完全归因到一个目标。PRESSURE 中一般等待一个目标进展再选下一个；CRITICAL 可使用第二个在途槽，不无界群发。

原型无进展规则：三个已确认退出的目标后，U 相对这三个动作前的样本仍未净下降至少 max(16 MiB,A/64)，暂停新增动作 1 s 并产生 no_progress 事件；下一轮仅在有新的可信压力样本和合适目标时重试。该规则可能受其他进程增长影响，是防误伤保护，不证明目标没有释放。没有合适目标时告警，绝不退化为终止受保护进程。

## 6. 目标选择与身份

只选择普通用户 backend。平台管理连接采用内部不可由普通 SQL 用户声明的保护标记；所有后台、复制进程和 SAL 默认排除。Taurus 平台管理连接须由部署策略明确标记；社区原型为保守安全起点将超级用户连接排除，意味着超级用户负载不在首版保护覆盖内。普通用户连接不能自行设置保护标记。

空闲指 idle 且无事务。idle in transaction 不纳入“低影响空闲”优先级，作为具有事务代价的候选处理。优先级为：超过最小收益阈值的真正空闲连接；其他允许处理的用户连接按私有内存近似值降序，平局按更早的采样/稳定身份排序。

OS RssAnon 可作便宜的初筛指标，不能称为精确私有内存或可释放量。仅对有限候选读取 smaps_rollup 的 Private_Clean/Private_Dirty 及显式大页私有项（可用时），保证采集成本有界。只读 RSS、没有可信角色或 PID 身份时不自动终止；记录 candidate_unavailable。候选指标只用于排序，不用于释放记账。

会话身份为实例启动代次、PG 进程槽代次和 PID；取消另包含语句序号。请求先写到对应槽，再用 PG 安全通知机制唤醒；目标自行核对身份。信号处理函数只设置待处理标志。槽重用必须先清理请求；不得仅凭 OS PID 发送迟到动作。

并行 worker 不独立成为目标。将 worker 的私有内存近似值归并到可信 leader 组；通过 leader 的既有查询取消/退出路径处理整个任务，跟踪 worker 清理但不自行向未知 worker 群发信号。

## 7. 取消、终止与 Taurus 清理

取消沿 PG 查询取消安全点进入 ERROR；终止沿正常会话结束路径进入 FATAL，保留 PG 的中断延迟、临界区、错误恢复规则。不使用 SIGKILL，不强行突破提交或 IPC 不可中断区。对没有及时响应的目标记录 action_timeout，不把超时解释为允许强杀。

实际退出可释放该进程的私有地址空间，包括 jemalloc 残留，但共享对象、其他进程持有的页和 SAL 缓冲不保证随之释放。无需等待 jemalloc background_thread，也不要求先取得 allocator stats。

Taurus enforce 上线前必须验证既有取消/断连契约：SAL 能识别过期请求，完成路径不会访问已释放私有缓冲，共享引用完成前不复用 IPC 槽，队列满时清理/完成仍可前进。SAL 无需提供内部内存统计。契约未经验证时只允许 observe，不对线上 Taurus 自动终止连接。

客户端看到明确的资源保护原因；取消使用查询取消语义，终止使用管理终止语义。未提交事务失败；发生在提交附近的断连可能使客户端不确定提交结果，禁止自动重试写语句。管理器不承诺业务级恰好一次。

## 8. 可观测性与故障行为

状态视图记录模式、L/U/H、阈值及平台模板版本、样本年龄、控制状态、候选数、在途数、管理器心跳、最近无进展原因。

事件记录动作 ID、会话/语句身份、角色、排序指标及有效性、触发样本、动作/响应/退出时间、后续实例样本和结束原因；不默认记录完整 SQL 文本。事件环原型容量 256，覆盖时递增丢失计数，日志限速。

管理器重启后重新采样并核对共享在途状态，不重放旧请求；实例重启代次隔离所有旧动作。off 禁止新动作，但不能撤回已经执行的终止；observe 只记录模拟选择。采集/管理器故障明确告警，不宣称仍有保护。

客户端重连风暴、持续新增查询可能抵消释放收益。首版依靠现有连接上限、平台连接池退避及事件告警；这些外部条件要进入验收记录。新增连接/语句准入门控作为下一阶段能力，不暗含于本阶段。

## 9. PG18 集成位置与交付拆分

已核对的既有位置：

- src/include/postmaster/bgworker.h：无需数据库连接的共享内存后台 worker 注册接口。
- src/backend/storage/ipc/ipci.c：固定共享结构初始化。
- src/backend/tcop/postgres.c：语句代次、ProcessInterrupts、空闲等待唤醒与取消/退出。
- src/backend/storage/ipc/procsignal.c：新增有身份检查的请求通知。
- src/backend/storage/ipc/signalfuncs.c：参考现有取消/终止权限与语义；不通过 SQL 循环实现守护逻辑。
- src/backend/utils/misc/guc_tables.c：两个用户参数的校验和重载。

预计新增独立保护模块与 src/test/modules/test_memory_protector 测试模块；具体接口和文件拆分在实现计划中确定，不改造所有 MemoryContext 分配器。

交付顺序：A. observe 采集/候选/事件；B. fake pressure 下身份安全与取消/终止；C. 隔离 Linux cgroup 社区 PG 压测；D. Taurus SAL 清理认证与小范围 enforce。第二版统一推进全局内存记账和请求管理，详见下一节。

## 第二版范围：全局内存记账与请求管理

用户于本轮明确：第一版先完成实例压力保护；第二版再考虑全局内存记账，并做请求管理。以下只确定阶段边界，不作为第一版实现依赖，也不是已完成的第二版详细设计。

全局记账：统一实例、PG 会话/请求及并行 worker 组的归属，区分申请额度、实际已分配、进程残留和 cgroup 物理计费。共享内存按对象计一次，SAL/IPC 单独归属；暂时无法细分的分配保留为未归属项，不伪装成零。复用第一版采集源和身份机制，不将所有进程 RSS 累加当作实例内存。

请求管理：根据可用预算及真实压力决定准入、有界等待或拒绝，建立请求额度申请、归还和异常清理生命周期。优先覆盖普通 B-tree 建索引等内存需求和安全等待位置明确的请求，再逐步扩展 SQL 范围；不承诺第一步覆盖所有语句。持锁事务、嵌套执行等不能安全等待的路径采用只尝试准入或明确拒绝，禁止直接在任意内存分配点排队。

两版衔接：第二版以准入和并发控制减少压力事件；第一版保护器持续保留，处理预算误差、未归属内存、SAL 突发及其他超出请求管理范围的压力。归还请求额度不等于物理回收，后继请求仍须通过实例压力检查。

产品参数：第二版优先从实例规格和观测数据推导预算，按需开放少量覆盖项；不重新要求用户填写一长串分桶参数。SAL/IPC 内部容量规划可由云平台负责，具体口径和策略在第二版设计时确认。

第一版验收不依赖第二版的精细记账、预算参数、队列或 allocator 回收能力。第二版需单独验证排队可取消、公平性、超时、请求及 worker 清理、持锁等待边界，以及吞吐/失败率相对第一版的改善。

## 10. 验收

| 场景 | 必须证明 |
| --- | --- |
| cgroup 读取失败、无限/变更上限、祖先约束 | 不凭错误边界或旧样本误处理 |
| observe/off | 没有任何取消或终止动作 |
| 阈值边缘波动、超临界水位 | 有滞后、不反复误动作；紧急状态不等固定取消宽限 |
| PID/槽复用、快速连续语句 | 旧请求不会取消新语句或新会话 |
| 大查询取消后 jemalloc 残留 | 必要时正常终止，实测占用，不假报已释放 |
| 并行建索引 | leader/worker 协同退出，没有孤立 worker 或重复处理 |
| idle 与 idle in transaction | 选择顺序符合事务代价分类 |
| SAL 延迟完成、队列满、backend 退出 | 无悬空引用、过早复用或完成路径死锁 |
| SAL 自身持续增长 | 有无进展事件和动作限速，不终止 SAL |
| 提交、回滚、不可中断调用 | 不绕过 PG/Taurus 安全点；超时可诊断 |
| 管理器重启、模式重载 | 不重放陈旧动作，不产生无界事件 |
| 高并发导数后建索引、连接重试风暴 | 记录 OOM、成功率、吞吐、P99、终止数、实际释放延迟和恢复进展 |

隔离 Linux cgroup 执行压力测试，禁止在开发者宿主机制造全局 OOM。约定矩阵内目标为零实例 OOM/异常重启，同时预先定义有效吞吐、成功率及完成时间门槛，不靠清空全部会话通过。尚无实测，不声明达标。
